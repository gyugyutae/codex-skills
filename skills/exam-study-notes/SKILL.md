# 시험대비 문서 만들기

사용자가 준 자료·질문만을 근거로 **필수 내용을 보존한 최소 글자 수**의 인쇄용 노트를 만든다. 일반적으로 중요해 보인다는 이유로 시험 범위를 확장하지 않는다.

## 범위와 근거

- 사용자 메모, 이미지의 보기·채점 결과, 지정 문서, 이전에 합의한 프로젝트 내용을 먼저 읽는다. 자료마다 원문 사실, 사용자 질문, 교수 시험 예고, 프로젝트 적용, 오류·충돌을 구분한다.
- 작업용으로 `요청 항목 → 근거 위치 → 수록 위치` 대응표를 만든다. 최종 노트에 이 관리표를 자동 추가하지 않는다.
- `시험)` 등 사용자가 교수의 출제 예고라고 명시한 항목만 시험 예고로 강조한다. 모델의 중요도 판단을 교수 지시처럼 쓰지 않는다.
- 질문에 필요한 답변·풀이·오류 교정은 포함한다. 요청하지 않은 이론, 공식, 세부 분류, 예제는 보충하지 않는다. 진위가 불명확한 강의 문구는 강의 주장과 검증 사실을 구분한다.
- 프로젝트 적용을 요청하면 해당 자료의 액터·기능·흐름·용어를 따른다. 제안 설계, 구현 상태, 검증 결과를 혼동하지 않는다. 외부 엔티티/액터, 메시지/클래스 책임, 요구/품질 시나리오의 일관성을 점검한다.
- 수치·일정·정확도·성능 목표를 임의로 만들지 않는다. 기존 수치는 출처·단위를 보존한다. 예시 작성에 새 목표가 필요하나 미합의이면 미정으로 구분한다. 강의 예제 수치를 프로젝트 확정 목표로 옮기지 않는다.

## 압축

- 정의는 핵심어와 짧은 문장, 비교는 표, 절차는 화살표 순서로 쓴다. 중복 정의·도입·결론·장황한 설명을 제거한다.
- 의미를 구별하는 조건·주체·단위·예외·화살표 방향·필수 요소는 남긴다. 용어만 나열해 구별할 수 없게 만들거나 글꼴을 줄여 분량을 맞추지 않는다.
- 프로젝트 답안에는 요구된 구성요소를 모두 넣는다. 예: Who/What/Why, 품질 시나리오 6요소. 이 특정 과목의 개념을 다른 과목 노트에 자동 삽입하지 않는다.
- 문제 모음은 사용자가 원할 때만 만든다. 제외 요청이면 새 노트에 문제·해설 구역을 넣지 않는다. 기존 별도 문제 파일은 유지한다.
- 문제를 요청하면 원문 질문·필요한 표·보기와 **각 문제 바로 아래** 정답·짧은 해설을 제공한다. 기존 문제도 빠뜨리지 않는다. 사용자의 답안 피드백 요청은 정오·고칠 이유·시험용 답안을 짧게 제시한다.
- 계산은 식→대입→결과·단위만 남긴다. 이미지의 채점값과 계산이 다르면 둘을 구분하고 불일치를 설명한다. 틀린 채점값을 맞추려고 수치를 바꾸지 않는다.

## 파일과 인쇄

- 기존 자료를 수정하라는 지시가 없으면 새 사본을 만든다. 노트 정리 요청이 원본 PPT/앱 수정 허가는 아니다. 이미 생성한 별도 파일도 요청 없이 삭제하지 않는다.
- 기본 산출물은 검색 가능한 PDF와 수정 가능한 Markdown 또는 HTML. A4 세로, 흑백에서도 구별되는 표·강조, 읽을 만한 한글 글꼴을 사용한다.
- 환경에 맞는 렌더러를 쓴다. Markdown/HTML→PDF가 적합하면 [scripts/render_notes.py](scripts/render_notes.py)를 사용한다. 페이지 수를 억지로 고정하지 않는다. 의도한 주제 경계만 분리한다.
- 모든 페이지의 글자·표·그림 겹침, 잘림, 한글 글리프, 미변환 Markdown, 화살표/조건 레이블을 확인한다. PDF 텍스트·페이지 경계 검사만으로 시각 검사를 대체하지 않는다.
- 압축 전후에는 문제 포함 여부를 맞춰 비교한다. 감소율은 같은 범위의 실제 추출 텍스트로 계산하고 기준을 밝힌다. 페이지 감소만으로 내용 보존을 주장하지 않는다.
- 작업용 대응표로 누락·범위 확장을 재점검한다. 원본 보존 여부와 최종 링크를 짧게 전달한다. 사용자의 개인 강의·프로젝트 원본을 스킬 저장소에 포함하지 않는다.
