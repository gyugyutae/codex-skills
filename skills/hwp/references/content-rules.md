# Personal information and evidence

- Use current user instructions, then source form and [profile](../assets/profile.json).
  Resolve conflicting facts by recency and user statements. Do not infer year from semester count.
- For missing/stale facts, discover the user's cmds Wiki, read AGENTS.md and Core Context.md,
  then relevant profile/source notes. Follow its query rules for substantial synthesis.
- Examples guide wording/format, not evidence of another month's work. Never invent activity
  dates, durations, participants, deployments, expenditures or measured savings. A monthly
  total does not establish session dates/hours. Distinguish capture, work, commit and submission dates.
- Inspect screenshots before captioning; preserve original pixels, identify capture dates
  and mock/emulator environments. Prefer UI/results over code walls. Current reruns and
  repository benchmarks do not prove the user's past work or measurements.
- Apply the current form's evidence count, recognized hours, lunch and course-conflict rules.
  Only the bundled 2026-10 RISE form uses [RISE context](rise-context.md).
- Unknown values stay blank; preserve labels and report gaps outside the deliverable.
- Personal assets are authorized for private gyugyutae/codex-skills, not public reuse.
  Do not include credentials, unrelated Wiki content or others' private files. Read
  [asset provenance](assets.md) before reusing personal facts or example activity claims.
