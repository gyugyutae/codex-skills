# 시험대비 문서 만들기

사용자가 준 자료·질문만으로 **공부할 내용만 담은 검색 가능한 PDF**를 만든다. 정리본은 표·핵심 차이·암기법 중심으로 구성한다. 모의고사는 한 PDF 안에서 **문제 전체 → 새 페이지 → 정답·해설 전체** 순으로 배치한다. 기본 최종 산출물은 PDF뿐이다.

## 범위와 근거

- 사용자 메모, 이미지의 보기·채점 결과, 지정 문서, 이전에 합의한 프로젝트 내용을 먼저 읽는다. 자료마다 원문 사실, 사용자 질문, 교수 시험 예고, 프로젝트 적용, 오류·충돌을 구분한다.
- 작업용으로 `요청 항목 → 근거 위치 → 수록 위치` 대응표를 만든다. 출처 확인과 충돌·누락 점검은 내부 작업으로 유지한다.
- `시험)` 등 사용자가 교수의 출제 예고라고 명시한 항목만 시험 예고로 강조한다. 모델의 중요도 판단을 교수 지시처럼 쓰지 않는다.
- 질문에 필요한 답변·풀이·오류 교정은 포함한다. 요청하지 않은 이론·공식·분류·예제로 범위를 넓히지 않는다. 강의 주장과 확인된 사실을 내부적으로 구분하고, 불명확한 주장을 확정 사실로 바꾸지 않는다. 충돌 때문에 정답을 확정할 수 없는 문항은 출제하지 않는다.
- 프로젝트 적용을 요청하면 해당 자료의 액터·기능·흐름·용어를 따른다. 제안 설계, 구현 상태, 검증 결과를 혼동하지 않는다. 외부 엔티티/액터, 메시지/클래스 책임, 요구/품질 시나리오의 일관성을 점검한다.
- 수치·일정·정확도·성능 목표를 임의로 만들지 않는다. 기존 수치는 출처·단위를 보존한다. 예시 작성에 새 목표가 필요하나 미합의이면 미정으로 구분한다. 강의 예제 수치를 프로젝트 확정 목표로 옮기지 않는다.

## 압축

- 정의는 핵심어와 짧은 문장, 절차는 화살표로 쓴다. 글자가 많은 부분은 가능한 한 항목·의미·조건을 나눈 표로 바꾸고, 비교표는 같은 기준으로 주요 차이를 나란히 보여 준다. 긴 문단을 그대로 표 한 칸에 넣지 않는다.
- 헷갈리는 개념에는 구별 기준을, 순서·목록에는 짧은 두문자·묶음·연결어 등 외우기 쉬운 방법을 붙인다. 암기법은 자료의 의미·순서·예외를 바꾸지 않으며 새 시험범위를 추가하지 않는다. 중복 정의·도입·결론은 제거한다.
- 의미를 구별하는 조건·주체·단위·예외·화살표 방향·필수 요소는 남긴다. 용어만 나열해 구별할 수 없게 만들거나 글꼴을 줄여 분량을 맞추지 않는다.
- 프로젝트 답안에는 요구된 구성요소를 모두 넣는다. 예: Who/What/Why, 품질 시나리오 6요소. 이 특정 과목의 개념을 다른 과목 노트에 자동 삽입하지 않는다.
- 문제 모음은 사용자가 원할 때만 만든다. 제외 요청이면 새 노트에 문제·해설 구역을 넣지 않는다. 기존 별도 문제 파일은 유지한다.
- 문제를 요청하면 지정한 유형·문항 수를 맞추고 질문·필요한 표·보기만 먼저 모두 제시한다. 마지막 문제가 끝나면 강제 쪽 나눔 후 **정답·해설** 구역에 같은 문항 번호 순으로 정답과 짧은 해설을 모은다. 문제 아래·문제 구역에는 정답·풀이·힌트를 노출하지 않는다. 문제와 정답은 별도 파일이 아닌 한 PDF의 앞·뒤 구역으로 나눈다.
- 예: 문제가 실제 5쪽까지 이어지면 정답·해설은 6쪽부터 시작한다. ‘5쪽’은 예시이며 문제 분량을 5쪽으로 억지로 맞추지 않는다. 4지선다·OX처럼 유형별 번호가 중복되면 정답에도 유형명을 붙여 대응시킨다.
- 주어진 원문 문제는 보존하고, 생성 문항은 자료 안에서 정답이 명확하도록 만든다. 이미 푼 답안의 피드백만 요청하면 해당 문항의 정오·고칠 이유·시험용 답안을 짧게 제시한다.
- 계산은 식→대입→결과·단위만 남긴다. 이미지의 채점값과 계산이 다르면 둘을 구분하고 불일치를 설명한다. 틀린 채점값을 맞추려고 수치를 바꾸지 않는다.

## 파일과 인쇄

- 기존 자료를 수정하라는 지시가 없으면 새 사본을 만든다. 노트 정리 요청이 원본 PPT/앱 수정 허가는 아니다. 이미 생성한 별도 파일도 요청 없이 삭제하지 않는다.
- 기본 산출물은 **검색 가능한 PDF만**이다. Markdown·HTML이 렌더링에 필요하면 임시 작업 폴더에 두고 최종 산출물 폴더에는 PDF만 생성한다. 사용자가 별도로 편집용 파일을 요청한 경우에만 해당 형식을 제공한다. 스킬 자체는 `SKILL.md`로 유지한다.
- PDF에는 제목·학습 내용·표·암기법·요청된 문제/정답/해설만 담는다. 출처·인용·근거 페이지·쪽 번호·머리말/꼬리말, 충돌 목록, 검증 상태, ‘근거가 조사되지 않았다’ 같은 작업 안내는 표시하지 않는다. 학습 내용 자체에 필요한 수치·단위·조건·예외는 보존한다.
- A4 세로, 흑백에서도 구별되는 표·강조, 읽을 만한 한글 글꼴을 사용한다. 환경에 맞는 렌더러를 쓰며 Markdown→PDF에는 [scripts/render_notes.py](scripts/render_notes.py)를 사용할 수 있다. 기본 명령은 PDF만 생성하고 쪽 번호를 넣지 않는다.

```bash
python3 scripts/render_notes.py /tmp/study/notes.md /path/to/시험정리.pdf --font /path/to/korean-font.ttf
```

- 페이지 수를 억지로 고정하지 않는다. 문제·필요한 표·보기는 한 덩어리로 배치한다. 정답·해설 구역 앞에는 `<!-- pagebreak -->` 등 렌더러의 강제 쪽 나눔을 넣는다. 표의 마지막 행만 외딴 페이지에 남지 않도록 조정한다.
- 모든 페이지의 글자·표·그림 겹침, 잘림, 한글 글리프, 미변환 Markdown, 화살표/조건 레이블을 확인한다. PDF 텍스트·페이지 경계 검사만으로 시각 검사를 대체하지 않는다.
- 압축 전후에는 문제 포함 여부를 맞춰 비교한다. 감소율은 같은 범위의 실제 추출 텍스트로 계산하고 기준을 밝힌다. 페이지 감소만으로 내용 보존을 주장하지 않는다.
- 작업용 대응표로 누락·범위 확장을 재점검하고, 문항 수·보기 수·정답과 해설 일치 여부도 확인한다. 모든 문제가 정답 구역보다 앞에 있고, 정답·해설은 마지막 문제 다음의 새 페이지에서 시작하는지 실제 PDF로 확인한다. 유형·번호별 문제와 정답이 일대일로 대응해야 한다. PDF만 생성되는지와 출처·쪽 번호·작업 안내가 보이지 않는지도 확인한다. 원본 보존 여부와 최종 PDF 링크를 짧게 전달한다. 실제 미완료 사항은 PDF 밖에서 알린다. 사용자의 개인 강의·프로젝트 원본을 스킬 저장소에 포함하지 않는다.
